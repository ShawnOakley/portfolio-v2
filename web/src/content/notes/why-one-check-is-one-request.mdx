# Why one check is one request

The page sends the whole brief in one request and gets one report back.

I looked at cutting a brief into sections and checking them in parallel. It
would not have been faster. CourtListener allows five requests a minute, and
parallel sections would share that allowance. The citation lookup already
takes up to 60 citations in a single call. Streaming the report would not help
either, because the hosting function stops at five minutes whether or not it
is streaming.

So a short brief finishes, and a long brief with support verdicts may run out
of time.
